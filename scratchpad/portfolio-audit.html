App shell & config

app/ · configs · README

layout.tsx is a server component with full metadata (metadataBase https://adarsh-vlsi.vercel.app/, OG/Twitter/canonical/robots, themeColor #fbf9f5) and a manual Google Fonts <link> (Caveat, Gloria Hallelujah, Plus Jakarta Sans, JetBrains Mono). page.tsx composes the client ExperienceRoot around a fully semantic server-rendered page — one hero section plus nine scene sections of sketch-card markup.

The twist: ExperienceRoot wraps {children} in a .sr-only div. The entire semantic page is visually hidden; everything visible is the fixed WebGL canvas plus overlay UI. The DOM page exists for crawlers and screen readers only.

HIGHDEAD
Two generations of scroll architecture coexist; the older one is fully orphaned. lib/gsap.ts wires Lenis ↔ ScrollTrigger → scrollStore, but initScroll has zero call sites — the lenis dependency is dead weight. The live camera is driven by useInfiniteCamera's raw wheel/key/touch listeners. Meanwhile body{overflow:hidden} makes the document unscrollable anyway.
MEDDEAD
Legacy "First Boot" layer survives as dead code. traceShader.ts, IntroScene.tsx (making tearShader transitively dead), IntroOverlay.tsx, ScrollHint.tsx, SoundToggle.tsx, CameraController.tsx, lazyScene.tsx, ExperienceContext.tsx — none are imported anywhere. Any of the context consumers would throw if rendered ("must be used within ExperienceProvider").
MED
SEO: the crawlable copy is in sr-only containers. Search engines discount visually-hidden text; the visible site is canvas-only with no DOM text. Also: metadataBase has a trailing slash vs Next's default no-trailing-slash redirects.
LOW
Config drift: next.config.mjs is literally empty; tailwind.config.ts maps bg-background/text-foreground to CSS vars that are defined nowhere; postcss lacks autoprefixer (custom config overrides Next's defaults); README is stock create-next-app boilerplate claiming next/font+Geist (neither true); page.tsx ends with a void skills; lint hack.

Corridor engine

InfiniteCorridorManager · CorridorSegment · Door · Avatar · EasterEggs

Streaming, not pooling: segments [N−1, N, N+1] around the camera's segment index floor((10 − z)/80), each mounting fresh at zOffset = 10 − idx·80 and unmounting when it falls out of the window. Every segment carries the same 4 doors (gallery/studio/about/contact at relZ −18/−32/−48/−62), 16 drei <Text> instances, plants, vents, and both easter eggs — so the corridor repeats identically every 80 units.

HIGHPERF
Mount/unmount churn instead of pooling. Each crossing constructs ~20 meshes + 16 Troika text geometries and GCs the old ones. Troika re-instantiation is the heaviest part. A pooled-group reposition (or instanced statics for plants/vents/baseboards) would collapse this.
MEDPERF
Always-on frame work, no distance gating. 12 doors × damp math + opacity writes, 3 hanging mice sin/cos, all running even far behind/ahead of camera; doors behind the player keep raycast targets live. Per-frame array literals + double .includes diff in the manager.
MED
Avatar flipbook through React state. 9 separate webp frames advanced ~8.3 fps by setFrameIndex — a React re-render 8×/sec to swap a texture map. Should be a single texture array + material.map swap via ref, or a spritesheet.
MED
HallwayScene coexists with the corridor stream. A 1000-unit finite hall (width 40, grid helpers, SCENES-driven placeholder doors) vs the live 7-unit-wide infinite stream. If both mount, doubled scene; HallwayScene looks superseded/orphaned.
LOW
Easter-egg sound spam: the duck pot plays "paper" on every pointer-over re-entry, no guard. Hanging mouse has no hover cursor state.
LOW
Legacy HallwayScene doors traverse the scene graph every frame (getObjectByName ×2 per door per frame) instead of holding refs.

Rooms

Gallery · Studio · About · Contact

All four rooms share one skeleton (header ✦ title ✦ + subtitle, same texture-loading idiom, same delta clamp, same palette) but hand-roll four different input systems — Gallery uses window wheel, Studio window drag, Contact drei Text onClicks, About nothing. onExit is declared in all four interfaces and consumed by none. Texture path conventions diverge (contact imports from backups/!).

HIGHROOM
Gallery wheel hijack. The room's window wheel listener slides the clothesline but never calls preventDefault — page scroll (body overflow hidden, so inert) and room motion compete; header claims swipe support, no touch handler exists.
MEDROOM
Studio drag rotates while dragging anywhere on screen — including over UI overlays. Window-level mousedown/move/up with no target check; also projects.slice(0, 6) magic cap silently drops projects if data grows; desk/phone textures loaded but never applied (dead loads).

Of the three shaders, only distortionShader is live (project-card hover warp + grayscale→color reveal, consumed via drei View portals). tearShader + IntroScene and traceShader are dead. Verdict & priorities

what to do next, in order

The architecture that's live — entrance → infinite corridor → four rooms — is coherent and charming. The problem is that two generations of the site coexist: the scroll-journey system (Lenis/ScrollTrigger, scrollStore choreography, traceShader "First Boot", IntroOverlay, CameraController keyframes, lazyScene, HallwayScene) and the current room-state system. The old layer is fully dead but still in the bundle, still in the repo, and still confusing every read of the codebase.

Priority order

  • 1 — Delete the dead layer. traceShader, IntroScene+tearShader, IntroOverlay, ScrollHint, SoundToggle, CameraController, lazyScene, HallwayScene, ExperienceContext, lib/gsap.ts + lenis dep, stage.ts (check consumers first). One commit, big diff, zero behavior change.
  • 2 — Fix the three user-visible bugs: camera ignoring the pause flag (lightbox scroll bleed), initial-Z clamp lurch (init refs at ≤12), résumé 404 (add public/resume.pdf or repoint links.resume).
